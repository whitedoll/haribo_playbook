# Comic Zip Reader

## User-visible outcomes

- zip 파일 하나를 업로드하면 압축 해제 없이 바로 만화책처럼 읽기 시작한다.
- 한 장 보기 ↔ 두 장 보기를 언제든 전환할 수 있다.
- 화면 좌/우 클릭으로 책장 넘기듯 이전/다음 장으로 이동한다.
- 넘기는 방향(왼→오 / 오→왼)을 설정할 수 있다.
- 홈 화면에서 보관 중인 zip(최대 2개) 목록을 보고 다시 열어볼 수 있다.
- 이미 읽던 zip을 다시 열면 마지막으로 보던 페이지부터 이어서 볼 수 있다.
- 페이지를 넘길 때 종이가 굽으며 넘어가는 애니메이션을 볼 수 있고, 원하면 끌 수도 있다.

## Approved scope

- zip 업로드(파일 선택 버튼), 이미지 파싱 및 순서대로 읽기
- 한 장/두 장 보기 전환
- 좌/우 클릭 페이지 넘김 + 방향 설정
- 최근 zip 2개 보관, 3번째 업로드 시 가장 오래된 것 자동 삭제
- zip별 마지막으로 읽던 페이지 기억 및 이어보기
- 페이지 넘김 시 3D 페이지 커링 애니메이션 + 켜기/끄기 설정

## Acceptance criteria

- zip을 올리면 압축 풀기 단계 없이 첫 페이지가 바로 보인다.
- 두 장 보기에서 1페이지는 표지로 단독 표시되고, 이후 2-3, 4-5 페이지가 짝지어 보인다.
- 오른쪽 클릭 = 이전 장, 왼쪽 클릭 = 다음 장이 기본값이며(오→왼 기본 방향), 방향 설정을 바꾸면 좌우 의미도 바뀐다.
- zip을 3개째 올리면 가장 오래된 zip이 확인 절차 없이 즉시 삭제되고 목록에서 사라진다.
- 이미지가 없거나 손상된 zip을 올리면 에러가 표시되고 목록에 추가되지 않는다.
- 목록에서 이미 읽은 zip을 다시 열면 마지막으로 보던 페이지(또는 두 장 보기였다면 그 스프레드)부터 보인다.
- 해당 zip이 자동 삭제(보관 2개 초과)되면 이어보기 기록도 함께 사라진다.
- 페이지를 넘기면 순간 전환 대신 종이가 굽으며 넘어가는 애니메이션이 재생된 뒤 다음/이전 페이지가 보인다.
- 애니메이션이 넘어가는 방향은 실제 이동 방향(다음/이전) 및 읽는 방향(오→왼/왼→오) 설정과 일치한다.
- 한 장 보기에서는 보이는 페이지 전체가 한 장의 종이처럼 굽으며 넘어간다.
- 두 장 보기에서는 넘어가는 쪽 페이지만 낱장처럼 따로 굽어지고, 반대쪽 페이지는 그대로 유지된다.
- 애니메이션 재생 중에 다시 클릭하면 애니메이션을 기다리지 않고 즉시 다음/이전 페이지로 넘어간다.
- 애니메이션 표시 여부를 설정에서 켜고 끌 수 있고, 기본값은 켜짐이다.

## Settled constraints and rationale

- 오래된 zip은 확인 없이 즉시 자동 삭제한다 — 개인용 도구이므로 단순함을 우선한다 (사용자 확정).
- 페이지 정렬은 자연 정렬(숫자 인식)로 처리한다 — 파일명이 page2, page10처럼 되어 있어도 순서가 꼬이지 않게 한다.
- 넘기는 기본 방향은 오→왼이다 (사용자 확정, 만화책 방식을 기본으로 둔다).
- 애니메이션 재생 중 클릭도 항상 즉시 반영된다 — 애니메이션 완료보다 입력 반응성을 우선한다 (사용자 확정).
- 페이지 넘김 애니메이션은 기본값이 켜짐이고, 사용자가 끌 수 있다 (사용자 확정).

## Assumptions

- 업로드는 드래그앤드롭 없이 파일 선택 버튼만 지원한다.
- 지원 이미지 포맷은 jpg/png/webp/gif 등 일반 포맷이다.
- 초기 보기 모드는 한 장 보기이다 (사용자 확정).
- 이어보기 위치는 zip 단위로만 구분한다 (같은 zip을 다시 올려도 같은 파일로 인식되면 이어보기가 적용된다는 전제이며, 파일 동일성 판단 기준은 구현 시 정한다).

## Off-limits (out of current scope)

- 말풍선 대사 자동번역 — `PRODUCT.md`에서 이미 확장 기능으로 명시.
- 개인 서버/WebDAV/SFTP/Samba 등 외부 저장소 연동 — `PRODUCT.md`에서 이미 확장 기능으로 명시.

## Deferred points

- zip 용량이 큰 경우의 처리 방식은 구현하면서 확인하기로 함 (사용자 확정).

## Remaining risks

- zip 용량이 매우 크면 브라우저에서 처리 속도/메모리 문제가 생길 수 있다 (구현 중 확인 필요, 위 Deferred 항목과 연결).
- 같은 zip 파일의 "동일성" 판단 기준(파일명 기준인지 내용 기준인지)이 아직 정해지지 않아, 이어보기가 의도와 다르게 동작할 여지가 있다.
- 두 장 보기에서 한쪽 페이지만 독립적으로 굽는 효과는 일반적인 CSS 전환보다 구현 난이도가 높다. 필요하면 종이 넘김 효과에 특화된 라이브러리 도입을 구현 시점에 검토한다.
